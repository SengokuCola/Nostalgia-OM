# OM-3 裂像与对焦诊断

[OM-3 1.1 逆向研究增量与实机证据](RE-FINDINGS.md) 汇总了和上游主线对照后的发现，以及各项目前能验证到哪一步。

## 第十三版 · 清晰度裂像 + 全层相位诊断（待实机验证）

第十三版沿用第十二版的连续分页日志（`OM3MOD/ZSxxxxxx.BIN`），不新增任何闪存钩子，将每条样本扩展为 OMSW v3（128 字节/条），单次扫焦同时记录：

1. **中央取景边缘清晰度与实际绘制错位量**（`edge_sharpness`、`split_draw`）：解除 `ZAF.TXT` 对反差裂像的屏蔽，手动镜头在记录日志的同时按“越清晰、错位越小”实际绘制裂像，便于直接检验停环时错位量是否稳定。
2. **原厂 MF 对焦指示器**（`focus_indicator`）：直接调用原厂 `0x60153ee1` 并记录原始方向、状态、前值、计时与变更序号。静态逆向表明该指示器仅反映电子镜头的对焦环位置与转动方向，纯手动无触点镜头下预期恒为无效。
3. **Quad-Pixel PDAF 第 0–2 层与 `ZAFInfo`**（`pdaf_raw`、`zaf_info`）：包括传感器原始相位流开关与 4 槽 A/B 环索引、最新槽中央 A/B 像素哈希、TruePic X 硬件 PDAF 电源/忙状态、ZAF 信箱与 AF 状态门控、1053 区辅助数组中央格（526）及 `0xa33eabe4`。
4. **保留第十二版原有全部字段**：中央区 4 路工作/发布值与发布标记、快门事件号、可为空的镜头位置。`read_sweep.py` 兼容 v1 / v2 / v3 全部日志。

### 实机测试步骤（同第十二版卡目录结构）

1. 卡上放匹配的 `DCOLYMP/E1479999.BIN`、`OM3MOD/{GUIDES,LABELS,TONES}.BIN` 以及 `OM3MOD/FOCUS.TXT`、`ZAF.TXT`、`DEBUG.TXT`（可选 `BEEP.TXT`），保留原有个人 `LOOKS/CURVES/EDITS/BUNDLES`。
2. 静态照片模式、MF、后屏直方图取景；开机后半按一次快门并松开激活裂像与采样。
3. 固定机位对准中央高对比度静止目标：从近端慢转经过目视最清晰点到远端，再从远端转回近端；在起点、目视最清晰点、终点各停约 2 秒，并在目视最清晰处短暂半按并松开打标记。全程无需拍照。
4. 结束后再半按并松开一次快门，等卡灯熄灭后关机，用 `python research/focus-assist/read_sweep.py <OM3MOD目录> > sweep.json` 一次性解码全部 `ZS*.BIN`。

### 记录一次 MF 扫焦

1. 保留卡上 OM3MOD 目录中的 FOCUS.TXT、ZAF.TXT 和 DEBUG.TXT。装上可向机身报告位置的镜头，如 M.Zuiko 45mm F1.8。选择拍照模式、MF 和后屏直方图取景。开机后先半按一次快门并松开。
2. 固定机位，让中央对准光线充足、边缘清晰的静止目标。从近端缓慢转过最清晰的位置到远端，再反向转回。在起点、目视最清晰处和终点各停约两秒。要标记目视最清晰处，可以在该位置短暂半按并松开。全程无需拍照。
3. 最后松开半按快门，等卡灯熄灭再关机。将 OM3MOD 中全部 ZS 加六位数字的 BIN 文件一起交给解码器。只有最后一页时无法还原全程。使用无电子触点的镜头时，位置可能为空，中央区数据仍按可用情况记录。

```powershell
python research/focus-assist/read_sweep.py G:/OM3MOD > sweep.json
```

每个样本同时包含序号、读取时钟、镜头位置及有效状态、中央区两组输入与各自标志、两路发布值、发布标记和最近一次快门事件号。相同发布标记表示重复观察到同一结果。只有标记更新且发布值有效，才能用来判断转过目标时是否变号。镜头位置是镜头报告的单位；手动镜头没有位置反馈时输出 null。读取发生在同一个采样回调，传感器与镜头各自的硬件更新时间可能不同。

老文件 ZAFZONE.BIN 仍保留最后 32 条快照。新增的 ZS000001.BIN 等文件每页最多 64 条，按开机分组编号。显示回调采样，后台通过 512 条缓冲区写卡。松开半按会请求写出末页，退出采样画面后后台也会写出不足一页的尾段。解码器报告序号缺口和不完整页。断电前尚未写出的尾段无法从卡上恢复。裂像仍使用原有的有效性检查；中央区输出用于比对，出现数值本身不能证明光学合焦或应当显示裂像。

## 第七版取景器连续刷新诊断

第六版实机日志记录到 EVF 的 IMG2 每场 64 行，成功提交时两场起点均为 177。用户仍看到上下两个大环、中间两个小环，整体高度随第六版压缩。本次开机拍照数为零。最后一次 EVF 取帧因显示寄存器在复制期间变化而中止。分场快照没有连续记录每一次拒绝的原因。

第七版在已测分场模式下跨空刷新保留仍归裂像所有的图层。一次单纯的输入地址轮换可以保留上一块完整的裂像，连续两次取帧失败则释放图层。EVF 的完成图块左上角带一个亮色 L，便于辨认重复出现在叠加前还是叠加后。日志的 EVF_MISS 行累计记录仅地址变化、其他显示变化、以及因地址轮换保留旧帧的次数。活动快照末尾五个字依次是已锁存的 IMG2 地址、步长、横向窗口和两场的纵向窗口。

## 第六版取景器分场测试

第五版实机日志记录了 EVF 的 `SYNC1=1`、`SYNC4=410` 和 1024×384 的场区域。第六版在这个时序下，把面板中央的 128×128 裂像按每场 64 行提交，并同时设置两场的纵向起点。日志的 `EVF_POST` 行新增了 IMG1 和 IMG2 的第二场起点。该实机布局下，预期 IMG2AREA2 为 `00B10040`，IMG2AREA3 为 `000000B1`。

## 对焦屏视觉原型（模拟器，未接入固件）

按用户要求跳过第二轮相机日志测试，先验证视觉核心。`screen.s` 是独立 MN10300 绘制函数，
`screen_model.py` 生成裂像／三角微棱镜映射，`screen_check.py` 编译并验证，
`screen_display.mjs` 将结果通过 OM-3 原厂 TH 显示函数送到模拟 TFT/EVF。

- 128×128 YCbYCr 区域，移动完整色度像素对；支持关闭、强度 0–8、纹理相位。
- 强度由测试程序指定，**不是镜头位置、真实离焦量或自动合焦判断**。
- 只在调用方提供的独立源、目标和映射缓冲区工作；拒绝越界、重叠和错误映射。
- 26 项原生指令测试逐字节符合模型；TFT/EVF 各三种显示状态通过模拟显示通路。
- 预览由自绘测试图生成，非相机截图。没有修改可刷固件，也没有写 SD 卡。

复现（使用已有开发环境）：

## 在相机上比较两种镜头

使用匹配的固件和 GUIDES.BIN；打开日志需要 SD 卡存在 `OM3MOD/DEBUG.TXT`。
包中只带固件、匹配的 GUIDES/LABELS/TONES 和 DEBUG.TXT，不替换个人 LOOKS/CURVES/EDITS/BUNDLES。
采用之前相同的安装流程；安装完成后机身语言选简体中文。

1. 固定相机和一个有细节的静止目标，光线充足。固定曝光、ISO 和光圈，原生电子镜头明确切到 **MF**，关闭半按自动对焦。
2. 第一轮开启峰值对焦，记录镜头型号。保持目标位于画面中央，同一轮不要改变取景或曝光。
3. 开机后先半按一次，等待 3 秒。把焦点调到目标前方，轻按并松开快门一次；不要拍照。
4. 等待 3 秒，用原厂放大功能确认目标清晰，退出放大，再轻按并松开一次。
5. 等待 3 秒，把焦点调到目标后方，轻按并松开一次。等 3 秒后关机。
6. 取出卡，将 `OM3MOD/CADLOG.TXT` 和 `OM3MOD/CFPROBE.BIN` 一起复制到电脑的 `native-peaking-on` 文件夹。
7. 关闭峰值对焦，重新开机，重复同样的三次调焦，保存两份文件到 `native-peaking-off`。
8. 关机换上转接／无电子触点手动镜头，重复步骤 1–7，分别保存到 `manual-peaking-on` 和 `manual-peaking-off`。
   没有距离指示器显示也正常。先完成 45mm F1.8 的一轮也可以；不要为了凑齐测试伪造镜头信息。

每份日志保留最后 8 个快门事件（半按和松开各算一次），顺序最新在前。
请同时记录三次操作的先后、镜头型号及观察到的指示器变化。
关机换镜头，每轮分别保存两份文件，避免下次开机覆盖；同一轮不要增加额外半按，否则会挤掉较早记录。

## 日志含义

`FOCUS PROBE 2` 下的 `FP` 行包含（与第一版相同）：

| 字段 | 含义 |
| --- | --- |
| FP 后的数字 | 本次开机的日志事件编号 |
| valid | 原厂镜头记录有效标志的快照 |
| status | 原厂镜头状态字的十进制原值 |
| inhibit | 指示器抑制字节原值 |
| dir | 指示器方向状态原值；不是已验证的前后离焦方向 |
| record | 镜头记录有效且指针通过地址/对齐检查时为 1 |
| pos / lo / hi | 镜头记录 +40 / +22 / +36 的有符号 16 位原值；非米、非离焦量 |

`record=0` 时后三项填 `-32768`，表示未读取。快照没有锁定镜头任务，字段不保证同一时刻，
也没有传感器帧时间戳；因此变化只能证明镜头状态变化，不能证明合焦精度或实时相位信息可用。

采样沿用已有 DEBUG.TXT 门控和日志写入节流，不增加启动工作，不发送 AF/镜头运动命令，
不改变原厂对焦设置，也不触碰实时图像缓冲区。诊断版不代表裂像功能已成立。

`CFPROBE.BIN` 可用 `python3 research/focus-assist/read_contrast.py CFPROBE.BIN --out contrast.json` 解码。
解码器核验文件长度、版本、事件环和逐记录校验值。输出原始三通道数值、配置、调试计数和复制前后状态；
暂不选取“中央区域”、计算合焦分数或判断前后离焦。计数受原厂调试开关控制，零值不表示无数据；
状态不变也不能证明快照新鲜或一致。需要将多轮实测与肉眼确认的清晰位置比较。

## 第七版实测与第八版相位裂像实验

第七版的 XPan 快捷菜单图标已通过机主验证。上一次新卡只写了固件和 GUIDES、LABELS、TONES，遗漏了启用裂像的 `OM3MOD/FOCUS.TXT`。已刷第七版的机身只需补这个文件，关机再开机，在静态拍照模式半按一次，再用 INFO 切到直方图取景。冷启动黑屏的实机结论仍待确认。

从本仓库的 WSL 终端运行 `bash research/focus-assist/local-build.sh out-local/my-build`。脚本使用已安装的 `caduceus-om3-dev:zh-cn` 镜像及 `/opt/caduceus-om3-dev` 工具链，构建、测试和 SD 卡目录均生成在仓库的 `out-local/my-build/`。每次使用新的目录名。`card/` 中的目录可以复制到测试卡，文件清单见同级的 `card.sha256`。

OM-3 1.1 的原厂 ZAFInfo 输出例程在 `0x609354db`。按其格式串、参数顺序和加载指令，可以对应到以下只读诊断字段。偏移以 `0xa33d1dd4` 为基址。

| 偏移 | 含义 | 类型 |
| --- | --- | --- |
| +1 | IsRanging，原厂测距状态 | u8 |
| +4 | 本次结果的时间值，初始化为全 1 | u32 |
| +10 | Area，原厂选用的区域编号 | u16 |
| +12 | defmm，带符号离焦候选值 | i16 |
| +16 | defpls，原厂以十进制有符号数打印的脉冲值 | i32 |

生产路径 `0x60935012` 使用原厂时钟检查样本年龄，以 `0x6090b234` 取得的时间值去重。`0x609351b7` 取当前区域，将 `0x6090ae42` 的返回值写入 defmm，再写入 defpls。`-32768` 是 defmm 的无效值。原厂按多步更新结构，采样时复查时间值和测距状态，仍有跨任务读取的时序限制。单位、光学前后焦符号约定、Area 在画面的位置、MF 下的更新率均需实测。

第八版测试包同时带 `FOCUS.TXT`、`ZAF.TXT` 和 `DEBUG.TXT`。前两个启用相位方向实验，最后一个启用日志。没有 ZAF 标记时沿用反差裂像。实验模式要求测距有效、样本未过期，而且同一区域的两次不同时间样本方向一致。负、零、正分别显示为反向错开两对色度像素、对齐、正向错开两对色度像素。位移固定，便于先验证方向。得不到合格样本时让出叠加层。

实机验证时，固定机位，对准一条穿过画面中心的清晰竖边，使用单点中央区域，慢慢从近焦转到清晰再转到远焦。两侧各停一下，再半按一次写入 `OM3MOD/FOCUSTRC.BIN`。推荐先用 45mm F1.8 的 MF，再用无电子触点镜头独立记录。解码命令为 `python research/focus-assist/read_focus_trace.py FOCUSTRC.BIN`。第二版格式的 `phase` 包含原厂时间值、区域、测距标志、defmm 和 defpls。只有成功发布的行给出实际采用的位移。模拟器可以验证相反方向的像素和无数据时撤层；光学输入由测试数据代替。
## 第九版镜头驱动日志

OM-3 1.1 的 AF 例程 `0x6098a784` 取得有符号的 16 位计算值。读取函数是 `0x609a0f26`，地址是 `0xa33eabe4`，初始化值是 -32768。调用点 `0x6098a7e5` 把该值交给驱动选择例程。它有同步、异步及换算成绝对目标位置的分支。此变量也是原厂 `1dmm` 调试输出的一项。驱动入口采到的 AF 变量是当时的快照，仍需实测是否属于同一帧。

同一个读取函数出现在 C-AF 序列的 `0x609a69ad`。原厂 `fcs ip set2` 帮助将第 1 位命名为 `CAF_SEQUENCE`，命令处理函数选择第 5 组掩码（地址 `0xa33f3634`）。序列在此位开启时将刚读到的值打印为 `1dmm`。第九版读取已有数据，无需开启原厂调试开关。

微四三的取景驱动另可直接组装请求。原厂 `fcs_lens_mfts_move_lens` 将目标写入 `lv.iaf_target`。`fcs_lens_mfts_move_lens_ofset_vd` 将移动量写入 `lv.ofs_move`，并写入时长参数 `lv.ofs_time`。两条路径都有独立的提交点。字段布局由原厂打印这些具名参数时的加载指令与实际请求的构造代码交叉核对。

| 解码类型 | OM-3 1.1 调用点 | 记录值 |
| --- | --- | --- |
| sync_def / async_def | 0x60901b91 / 0x60901bc9 | 驱动请求的有符号 DEF 参数 |
| main_def / sub_def | 0x60901bf2 / 0x60901c05 | 主、副驱动请求的有符号参数 |
| absolute / absolute_direct | 0x60901b15 / 0x6092f70b | 绝对目标位置、原厂方向标志 |
| mft_move / mft_move_alt | 0x609ae38b / 0x609ae396 | iaf_target、iaf_flg |
| mft_offset_vd / mft_offset_vd_sim | 0x609aeb13 / 0x609af02d | 有符号 ofs_move、ofs_time |

打开 FOCUS 和 ZAF 标记后，第一次半按启用记录。每次经过上述调用点写一条 RAM 记录，包括机身 31 位时钟的 `submit_tick`、请求类型、请求值及同刻的 AF 变量。时钟回绕时用 `(new - old) & 0x7fffffff` 计算间隔。它标记提交动作，曝光采样、驱动接受命令及镜头到位的时刻仍未知。显示回调和能否绘制裂像均不影响该环形记录。DEBUG 标记启用快门日志保存，松开半按后可读取 `OM3MOD/LENSDRV.BIN`。计数为零表示本轮启用后尚未观测到这些调用点，环形缓冲保留最近 64 次提交。

解码命令为 `python research/focus-assist/read_lens_drive.py G:/OM3MOD/LENSDRV.BIN`。用 45mm F1.8，选择中央单点 C-AF，对准远处有纹理的物体。保持半按，在中心对焦框内放入、移开近处的书，再松开半按。记下切换顺序，尤其是最后一次切换方向。可用移动量与 AF 值的符号验证近远切换，绝对目标应按相邻目标的变化解读。相位测量来源、光学正负号约定及 MF 可用性仍须分别验证。

## 第十版 AF 写入日志

第九版 45mm F1.8 的 C-AF 实测捕获 15 次绝对位置请求，其中两次读到 +111 和 +109，其余读到 -32768。第十版在原厂写入函数 `0x609a0e4f` 记录传入的低 16 位，包括归零和失效。两个计算分支的调用点是 `0x6099ebeb` 和 `0x6099eed3`，初始化在 `0x609a0db7` 写入 -32768。新增观察不改变写入值或镜头控制参数。

`AFWRITE.BIN` 保留最近 128 条记录。连续无效写入仅保留第一条；连续相同的有效写入逐次记录。每条包含写入时刻、带符号的 AF 值，以及写入者返回地址的低 16 位。`read_af_writes.py` 将已知返回地址映射到对应的调用点，将无效值解码为 `null`。原有 `LENSDRV.BIN` 独立保留最近 64 次镜头请求。二者使用同一 31 位时钟，便于对照 AF 值何时发布、何时失效，以及镜头何时收到新目标。它们没有逐帧关联编号；实机记录还需验证光学方向及其对 MF 的适用性。

启用标记与第九版相同。先半按并松开一次，再按住半快门做一次远 → 近 → 远切换，松开后等写卡灯熄灭。两份日志都在卡的 `OM3MOD` 目录。解码新文件可用 `python research/focus-assist/read_af_writes.py G:/OM3MOD/AFWRITE.BIN`。

## 第十一版中央区相位诊断

OM-3 1.1 的 ZAF 处理函数 `0x609aa79b` 遍历 39 × 27 个区域。第十一版在取景刷新和快门日志保存时，观察中心格（第 14 行、第 20 列）。`ZAFZONE.BIN` 保留最近 32 次采样，每两条至少间隔 200000 个机身时钟计数。读取时刻与 `AFWRITE.BIN`、`LENSDRV.BIN` 使用同一时钟。

每条记录包含两套处理输入各自的前两路带符号数值和筛选标志。对这两路，原厂遇到标志 1 或 2 时会把输出设为 -32768。同时采样已发布槽位里的中央输出、处理分支、就绪位和发布标记。输入工作区由机身异步写入，单次读取不能证明这些数值属于同一曝光帧；判断更新需要对照多条记录的发布标记和有效值。只有识别出原厂分配的整对缓冲区才读取输入。槽位无效或观察期间发生切换时，解码器将发布结果留空。

实测时用中央固定目标、纯 MF 和后屏直方图。半按松开一次启用记录，缓慢转过清晰点，在两侧各停一下，最后半按松开一次保存。解码用 `python research/focus-assist/read_zaf_zone.py G:/OM3MOD/ZAFZONE.BIN`。判断能否用于裂像，需要看手动越过合焦点时有效值是否稳定反号，以及静止时是否保持。双路光瞳图像、输入单位和光学方向仍待验证。
